*glean.txt*	A foldable, navigable git diff reviewer for Neovim

==============================================================================
INTRODUCTION						*glean*

glean renders the diff between two refs in a single foldable, navigable buffer.
The buffer is a read-only projection of a review model; all interaction happens
through actions that mutate a persistent review store, so seen-marks and
comments survive across sessions.

Requires Neovim 0.12+. glean has no external plugin dependencies — it shells
out to `git`.

==============================================================================
COMMANDS						*glean-commands*

							*:Glean*
>
	:Glean                  review current branch + dirty work tree
	:Glean {base}           review {base} + dirty work tree
	:Glean {base} {target}  review {base}..{target} (no dirty work tree)
<
`:Glean` with no args opens the "dirty" review: on a feature branch the base is
the fork point (merge-base) from the default trunk, so you see the branch's own
commits plus uncommitted edits; on the trunk itself the base is the upstream
tracking ref, so you see unpushed commits plus uncommitted edits.

A live work-tree review refreshes on save and on regaining focus (with a 5s
safety-net poll for changes made outside the editor) and re-renders in place as

files change, preserving the cursor and your collapse state.

Reopening the same `base..target` reuses the existing listed buffer rather than
spawning a duplicate, so you can jump to a source file and return via the
buffer list / <C-^>.

==============================================================================
SCOPES							*glean-scopes*

Toggle the scope with `S`:

combined (default)	the net `base..target` diff. Deletions are attributed
			to the commit that removed them; additions to the
			commit that introduced them (derived by composing the
			range's first-parent patches).

commits			every commit laid out flat. Seen-marks and comments
			are authored against a stable (commit_sha, path, line)
			identity here, and the same mark is reflected in the
			combined view.

==============================================================================
IGNORE WHITESPACE				*glean-ignore-whitespace*

Press `W` to toggle ignore-whitespace mode for the current review. The header's
scope label includes `ignore-whitespace` while the mode is enabled, and progress
counts include only visible changes. Seen marks and comments remain in the same
persistent review store and reappear unchanged when the mode is disabled.

The displayed diff uses Git's `--ignore-all-space`: whitespace is ignored when
comparing lines. Rendered text is not trimmed or normalized, so visible rows keep
their exact content and source coordinates. This does not mean every blank line
is removed; for example, a newly added blank line may remain a real addition.
Untracked files render identically in both modes because they have no pre-image.

==============================================================================
SEEN / COLLAPSE						*glean-seen*

Seen-ness is a flat set of line identities. A hunk is "seen" iff every
one of its changed lines is seen; files and commits roll up the same way. Seen
units render in a collapsible per-file "seen" section, and a contiguous seen
run inside an otherwise-unseen hunk collapses into a `✓ marked N lines` marker
row.

For committed changes a mark is a line number on a commit. For uncommitted work
"seen" means you signed off on a version of the line: glean remembers the
content you approved and compares it against the file as it is now, so only the
parts you subsequently change come back as unseen. Committing resets the seen
state for the files the commit touched.

Collapse state is ephemeral view-state (initialized from seen status, then
evolves independently and is never persisted).

==============================================================================
COMMENTS						*glean-comments*

Comments are content-addressed records attached per path and re-anchored to
their matching diff line on every render, so they follow the code as the diff
changes. A comment whose anchor disappears is flagged outdated and shown in the
file summary. A comment on a whitespace-only row hidden by ignore-whitespace mode
is instead labeled `Hidden by whitespace mode` in the summary. Pressing <CR> on
that entry disables the mode, reveals the row, and jumps to the inline comment.

The comment editor opens in a markdown split. Submit with <CR> (normal mode) or
by writing the buffer (`:w`); abort with `q` or <C-c>. Submitting an
empty/whitespace-only buffer is treated as an abort.

==============================================================================
KEYMAPS							*glean-keymaps*

Inside the glean buffer:

	m (normal)	toggle seen on the hunk/file/commit under the cursor;
			on a marker row/line, unmark that run
	m (visual)	mark the selected lines seen
	ac (visual /	text object selecting the hunk under the cursor
	  operator)	(e.g. `vac`)
	=		toggle collapse (section, file, commit, or marker row)
	c (normal)	comment on the current line
	c (visual)	comment on the selected span
	i		edit the comment under the cursor
	dd		delete the comment under the cursor
	dc		delete a comment attached to the current line
	u / <C-r>	undo / redo (seen, comment, collapse actions)
	]c / [c		next / previous hunk
	]f / [f		next / previous file
	<CR>		jump to the source line (live file when the ref is
			HEAD, else a read-only `git show` buffer)
	D		open an ephemeral side-by-side diff for the hunk
			under the cursor
	S		toggle scope (combined / commits)
	W		toggle ignore-whitespace mode (Git --ignore-all-space)
	q		close the window

==============================================================================
SETUP							*glean-setup*

							*glean.setup()*
>lua
	require("glean").setup({
	  default_base = "main",   -- trunk used for fork-point / upstream resolution
	  ignore_whitespace = false,  -- initial Git --ignore-all-space display mode
	})
<
`setup` registers the `:Glean` command and defines the highlight groups
(re-derived from `DiffAdd`/`DiffDelete` on every `ColorScheme`).

Options:

	default_base	(string) Trunk used for fork-point / upstream
			resolution. Default: "main".

	ignore_whitespace
			(boolean) Start newly opened reviews in ignore-whitespace
			mode. Toggle the active review with `W`. This affects the
			display and progress counts, not exact source text or
			persisted review data. Default: false.
